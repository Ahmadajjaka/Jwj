# خطة تطوير نظام المامو المحاسبي — صلاحيات الاعتماد، تأريخ الفواتير، إدارة سحابة Firebase، وضغط قاعدة البيانات

تهدف هذه الخطة إلى إضافة أربع قدرات تشغيلية وإدارية متكاملة داخل نظام **محاسب خردوات المامو (MAMO ACCOUNTING)** تشمل: نظام قائمة انتظار لموافقة الأدمن على تسجيل المستخدمين الجدد وتحديد طبيعة عملهم وصلاحياتهم، منتقي تاريخ ووقت دقيق لكل فاتورة بيع وشراء مع فلترة زمنية، أداة حذف البيانات المخزنة على سحابة Firebase من لوحة تحكم الأدمن، ونظام ضغط حقيقي لقاعدة البيانات وتنظيف السجلات القديمة والنسخ الاحتياطي المضغوط لتوفير مساحة تخزين كبيرة.

---

## قرارات المستخدم المعتمدة ومراجعة النطاق

> [!IMPORTANT]
> تم تأكيد الخيارات الأربعة التالية من قِبل المستخدم خلال مرحلة التوضيح وسيتم تنفيذها مباشرة كما هي معتمدة:
> 1. **آلية موافقة الأدمن على المستخدمين الجدد**: **قائمة انتظار يقبلها الأدمن ويحدد الدور والصلاحيات** (يدخل الحساب الجديد في حالة انتظار ولا يُفعَّل إلا بعد موافقة الأدمن وتعيين الدور الوظيفي والصلاحيات التفصيلية أو رفض الطلب).
> 2. **التحكم بتاريخ فواتير البيع والشراء**: **منتقي تاريخ ووقت لكل فاتورة بيع وشراء مع فلترة بالتاريخ** (يختار المستخدم التاريخ والساعة لكل فاتورة بيع أو شراء عند الإنشاء أو التعديل أو مراجعة OCR، مع شريط فلترة زمني مرن).
> 3. **نطاق حذف بيانات Firebase من لوحة تحكم الأدمن**: **خياران: حذف كل بيانات السحابة أو حذف أقسام محددة مع تأكيد PIN** (تأكيد ثنائي برمز PIN للأدمن قبل تنفيذ الحذف السحابي الكامل أو الانتقائي دون المساس بأمان الحسابات الأخرى).
> 4. **طريقة ضغط قاعدة البيانات لتوفير المساحة**: **ضغط فعلي بـ VACUUM وتنظيف السجلات القديمة ونسخ احتياطي مضغوط GZIP** (مع عرض الحجم قبل وبعد الضغط والمساحة المحررة بدقة).

## 1. النظرة العامة والمفهوم الأساسي

- **ماذا تضيف التحديثات**:
  1. **بوابة اعتماد الموظفين وتعيين طبيعة العمل**: فصل مرحلة إنشاء طلب الحساب عن مرحلة تفعيل الصلاحيات بحيث يتحكم الأدمن (أحمد نوار المامو أو مالك النظام) في قبول كل مستخدم جديد وتحديد طبيعة عمله بدقة قبل السماح له بالدخول.
  2. **التأريخ المحاسبي الدقيق للمبيعات والمشتريات**: تمكين تسجيل كل فاتورة بيع أو شراء بتاريخها ووقتها الفعلي (حتى الفواتير المتأخرة أو المجدولة ضمن الفترات المحاسبية المفتوحة) مع فلترة فورية لسجلات البيع والشراء حسب التاريخ.
  3. **التحكم الكامل في سحابة Firebase من لوحة الأدمن**: توفير أدوات حذف انتقائي (أصناف، أطراف، فواتير، حركات وقيود) أو مسح كامل لبيانات المتجر المخزنة على Firestore بشكل آمن ومحصن برمز PIN وقواعد أمان محدثة.
  4. **محرك ضغط قاعدة البيانات وتوفير المساحة**: تقليص حجم ملفات قاعدة البيانات المحلية والنسخ الاحتياطية بشكل فعلي عبر إزالة الصفحات الفارغة (`VACUUM`)، دمج سجل الكتابة (`WAL Checkpoint`)، تنظيف السجلات التشغيلية المنتهية الصلاحية، ودعم ضغط `GZIP` في النسخ الاحتياطي.
- **الفئة المستهدفة**: مدير المتجر (الأدمن) لإدارة الموظفين والسحابة والمساحة، والمحاسبون والكاشير وأمناء المستودع لتسجيل الفواتير بتاريخها الدقيق.
- **القيمة الأساسية**: أمان تنظيمي أعلى، دقة زمنية كاملة للدفاتر والتقارير اليومية، سيطرة كاملة على تكاليف وحجم بيانات السحابة، وتقليص ملموس لحجم التخزين على الجهاز.

## 2. تجربة المستخدم والتصميم البصري

### أ. التدفقات التفاعلية لكل ميزة

1. **تدفق تسجيل الدخول وقائمة انتظار الأدمن**:
   - **عند التسجيل من شاشة الدخول**: يملأ المستخدم اسمه الكامل، المعرف/اسم المستخدم، كلمة المرور، ويمكنه اقتراح طبيعة العمل المطلوبة (كاشير، أمين مخزن، محاسب، مراقب). في حال وجود مالك نشط للنظام وعدم إدخال رمز موافقة فورية من المالك، يُحفظ الحساب بحالة **"بانتظار موافقة الأدمن"** (`PENDING`) ولا يُفعّل للدخول.
   - **عند محاولة الدخول بحساب معلق أو مرفوض**: تعرض شاشة الدخول الزجاجية بطاقة تنبيه واضحة تشرح حالة الطلب (*"طلبك بانتظار موافقة الأدمن وتحديد طبيعة عملك"* أو إشعار الرفض)، مع منع الوصول للنظام لحين الاعتماد.
   - **في لوحة تحكم الأدمن والإعدادات**: تظهر بطاقة بارزة في الأعلى بعنوان **"طلبات تسجيل الدخول المعلقة"** مع شارة عدد حمراء/ذهبية عند وجود طلبات. يضغط الأدمن على زر **"قبول وتحديد الدور"** لفتح نافذة منبثقة يختار فيها الدور الوظيفي (مالك، محاسب، كاشير/بائع، أمين مخزن، مراقب) ويضبط مفاتيح الصلاحيات الثمانية (رؤية الأرباح، إلغاء الفواتير، إدارة المخزون، المصاريف، الإعدادات، تعديل الأسعار، السحب والإيداع، اعتماد الجرد) أو يضغط **"رفض الطلب"**.

2. **تدفق منتقي التاريخ والوقت وفلترة الفواتير (المبيعات والمشتريات)**:
   - **عند إنشاء أو تعديل فاتورة بيع أو شراء (بما فيها شاشة مراجعة OCR)**: يظهر شريط تاريخ ووقت تفاعلي أعلى بطاقة الفاتورة يعرض التاريخ والوقت الافتراضي الآن مع زر **"تغيير التاريخ والوقت"** يفتح منتقي التاريخ القياسي (`Material 3 DatePickerDialog`) متبوعاً بمنتقي الوقت (`Material 3 TimePickerDialog`).
   - **في قوائم المبيعات والمشتريات**: يُضاف شريط شرائح فلترة زمنية أعلى القائمة: (`الكل`، `اليوم`، `هذا الأسبوع`، `هذا الشهر`، `تاريخ مخصص`) مع إظهار النطاق الزمني النشط وعداد الفواتير المطابقة وإجمالياتها.
   - **التكامل مع إقفال الفترات**: إذا اختار المستخدم تاريخاً يقع ضمن فترة محاسبية مقفلة، يظهر تنبيه فوري ويمنع الاعتماد لحماية الدفاتر المقفلة.

3. **تدفق حذف بيانات Firebase السحابية (من لوحة الأدمن)**:
   - داخل **لوحة تحكم الأدمن بقاعدة البيانات**، تتوفر بطاقة خاصة بإدارة التخزين السحابي تحت خيارين واضحين:
     - **حذف أقسام محددة من السحابة**: مربعات اختيار للأقسام (`المنتجات`، `الزبائن والموردون`، `الفواتير`، `القيود والسجلات والدفاتر`).
     - **مسح كامل بيانات السحابة للمتجر**: خيار أحمر تحذيري يحذف جميع المجموعات السحابية المرتبطة بحساب المتجر مع خيار الإبقاء على النسخة المحلية وإعادة تعيين علامات المزامنة (`isSynced = false`) حتى لا تضيع بيانات الجهاز بالخطأ.
   - **التأكيد الأمني**: أي عملية حذف سحابية تتطلب إدخال **رمز PIN الخاص بالأدمن** في حوار تأكيد مزدوج، مع شريط تقدم لحين انتهاء الحذف التسلسلي على دفعات وتحديث إحصاءات السحابة فوراً.

4. **تدفق ضغط قاعدة البيانات والنسخ المضغوط GZIP**:
   - في **لوحة تحكم الأدمن بقاعدة البيانات**، تعرض بطاقة **"ضغط قاعدة البيانات وتوفير المساحة"** الحجم الفعلي الحالي على القرص (ملف القاعدة + `WAL` + `SHM`) وعدد السجلات القابلة للتنظيف.
   - **خيارات التنظيف الذكي والضغط**:
     - اختيار مدة الاحتفاظ بسجلات التدقيق والمزامنة المنتهية وسجل تغير الأسعار ومحادثات المساعد (`أكثر من 30 يوماً` / `60 يوماً` / `90 يوماً` / `تنظيف طابور المزامنة المكتمل فقط`) مع حماية تامة للفواتير والمنتجات والديون والقيود المالية من أي حذف.
     - زر **"تنظيف وضغط قاعدة البيانات (VACUUM)"**: ينفذ التنظيف الآمن ثم دمج `WAL` وضغط `SQLite VACUUM` في الخلفية، ثم يعرض بطاقة نتيجة توضح: **الحجم قبل الضغط**، **الحجم بعد الضغط**، **المساحة الموفَّرة بالكيلوبايت/الميغابايت ونسبة التوفير %**.
   - **النسخ الاحتياطي المضغوط (`GZIP`)**: خيار تصدير مضغوط (سواء JSON مضغوط `.mamo.gz` أو مشفر `AES-256 + GZIP`) يقلص حجم ملف النسخة بنسبة كبيرة، مع كشف تلقائي عند الاستعادة سواء كان الملف مضغوطاً أم لا.

### ب. الهوية البصرية والاتساق مع النظام

- **الطابع البصري**: الحفاظ على هوية **خردوات المامو** الفاخرة (كحلي ليلي عميق وأبيض لؤلؤي ورمادي احترافي مع لمسات ذهبية)، وبطاقات زجاجية (`GlassCard`) بدون تعقيد رسومي مبطئ للأداء.
- **الاتجاه والخطوط**: دعم عربي كامل من اليمين إلى اليسار (`RTL`) مع توضيح الأرقام والتواريخ والعملات والأحجام التخزينية (`KB / MB`) بصيغة مقروءة.
- **عناصر Material Design 3**: استخدام `DatePickerDialog` و`TimePickerDialog` المدمجين، شرائح التصفية `FilterChip`، أزرار التبديل والاختيار بحجم لمس لا يقل عن `48dp`، وأيقونات `Material Symbols` الدالة (ساعة، تقويم، قفل، سحابة، ضغط ملفات).

## 3. القرارات الهندسية والمقايضات الرئيسية

1. **ترقية مخطط قاعدة البيانات المحلية (`Room Migration v2 -> v3`)**:
   - *الخيار المعتمد*: إضافة حقول حالة الاعتماد (`approvalStatus`، `requestedRole`، `loginIdentifier`، `requestedAtMs`، `approvedBy`، `approvedAtMs`) إلى جدول المستخدمين عبر ترحيل SQL محافظ (`MIGRATION_2_3`) مع القيمة الافتراضية `'APPROVED'` للحسابات القائمة.
   - *السبب*: يضمن ترقية سلسة دون مسح بيانات المستخدمين الحاليين ودون كسر جلسات الأدمن والموظفين المعتمدين مسبقاً.

2. **تنفيذ ضغط `VACUUM` خارج المعاملة النشطة (`SupportSQLiteDatabase`)**:
   - *الخيار المعتمد*: تشغيل `PRAGMA wal_checkpoint(TRUNCATE)` و`VACUUM` عبر اتصال قاعدة البيانات المباشر على خيط الإدخال/الإخراج (`Dispatchers.IO`) مع فحص الحجم الفعلي لملفات قاعدة البيانات قبل العملية وبعدها.
   - *السبب*: يفرض SQLite ألا يُستدعى أمر `VACUUM` داخل معاملة `@Transaction`؛ تنفيذه خارج المعاملة يضمن تحرير المساحة غير المستخدمة فعلياً على نظام الملفات دون أخطاء وقت التشغيل.

3. **تحديث قواعد أمان Firestore لحذف بيانات المالك مع الحفاظ على العزل الصارم**:
   - *الخيار المعتمد*: تعديل `firestore.rules` للسماح بالمسح (`allow delete`) حصرياً لصاحب المتجر الموثق (`isOwner(userId)`) على مستنداته ومجموعاته الفرعية، مع تغطية هذا المسار في اختبارات المحاكي (`firestore.test.js`) والتحقق من أن أي مستخدم آخر يظل مرفوضاً (`PERMISSION_DENIED`).
   - *السبب*: كانت القواعد الحالية تمنع الحذف كلياً (`allow delete: if false`)؛ السماح المشروط للمالك وحده يوازن بين تمكين ميزة الحذف في لوحة الأدمن ومنع أي عبث خارجي، مع إعادة تعيين حالة المزامنة محلياً بعد الحذف السحابي.

4. **الضغط المزدوج `GZIP + AES-256` في النسخ الاحتياطي مع التوافق الرجعي**:
   - *الخيار المعتمد*: ضغط الحمولة النصية JSON بخوارزمية `GZIP` قبل التشفير (أو كملف مضغوط مباشر) مع ترويسة تعريف ذكية تسمح بدالة الاستعادة بتمييز النسخ القديمة غير المضغوطة والنسخ الجديدة المضغوطة/المشفرة تلقائياً.
   - *السبب*: يضاعف `GZIP` كفاءة تقليص المساحة مقارنة بالنص الخام ويجعل التشفير أسرع وأصغر حجماً مع الحفاظ على استعادة النسخ السابقة دون مشاكل.

### نموذج البيانات وتدفق الحالة الرئيسي

- **كيان المستخدم والصلاحيات (`StaffUserEntity`)**: إضافة حقول حالة الاعتماد (`PENDING` / `APPROVED` / `REJECTED`)، الدور المقترح، المعرف، وتوقيت الطلب والاعتماد، بحيث يتحقق مسار تسجيل الدخول من أن `isActive == true` و`approvalStatus == "APPROVED"` قبل فتح الجلسة، وتتحقق لوحة الأدمن من جميع الحسابات المعلقة لعرضها في قائمة الانتظار.
- **الفواتير المؤرخة**: تمرير `invoiceDateMs` المختار من منتقي التاريخ والوقت عبر الواجهة إلى `MamoViewModel` ثم `AccountingRepository` لكل من فواتير البيع والشراء والتعديل ومراجعة OCR، مع التحقق من عدم الوقوع داخل فترة محاسبية مقفلة وتحديث قوائم العرض عبر فلتر زمني تفاعلي.
- **إدارة المساحة والسحابة**:
  - عملية الضغط تقرأ حجم ملفات قاعدة البيانات، تنفذ تنظيف السجلات غير الحرجة حسب مدة الاحتفاظ المختارة (طابور المزامنة المتزامن، سجلات التدقيق القديمة، سجل الأسعار القديم، وسجلات الذكاء الاصطناعي القديمة)، تطلق `PRAGMA wal_checkpoint(TRUNCATE)` و`VACUUM`، وتُرجع تقريراً بالبايتات والميغابايت الموفرة.
  - عملية الحذف السحابي تنفذ على دفعات عبر Firestore Batch لـ `products` و`parties` و`invoices` و`ledger_entries` (والملف الشخصي عند المسح الكامل) بعد التحقق من رمز PIN للأدمن وتوافق `firestore.rules`، ثم تعيد تعيين حالة المزامنة المحلية لضمان اتساق البيانات.
